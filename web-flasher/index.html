First boot & Wi-Fi setup

Join the open BirdNETMic-XXXXXX setup network. Choose your board and default mode. Streaming connects to home Wi-Fi; Recording can also use standalone Device Wi-Fi. Save the direct-access password shown by the wizard before finishing.

If the portal does not open, visit http://192.168.4.1. After setup, reconnect to your home network, or rejoin Device Wi-Fi with the saved password for standalone use. Find the board’s IP in your router, or use its unique mDNS name, such as esp32mic-a1b2c3.local, shown in its Web UI.

Connect to BirdNET

Choose Streaming after setup, then add the device’s RTSP stream to BirdNET-Go or BirdNET-Pi.

rtsp://<device-ip>:8554/audio1
rtsp://<device-ip>:8554/audio2

Recording instead? Select Recording, check the SD card, use Listen for a sound check and press Start recording. Standalone Device Wi-Fi works without a router. Turning Wi-Fi off saves power but requires reset or power cycling to reconnect; the device sleeps when the offline session ends. Read the field recording guide.

These paths also work with the device’s unique mDNS hostname when mDNS is available.

How are downloads counted?

One complete firmware file transfer counts as one download. USB flashing counts only the app image; bootloaders and partition files are excluded. Device OTA and direct downloads are counted separately. Retries and repeat downloads can count again; these numbers do not measure unique devices or successful installations.

Website history is limited to retained server logs. GitHub totals cover published firmware assets.

Website checks by our release scripts, HEAD requests, failed and incomplete transfers are excluded. GitHub provides raw asset download counts, including historical tests and automation that cannot be separated. A release’s total adds its four boards and all download types. Historical transfers whose version cannot be verified are listed as “Unassigned”.
