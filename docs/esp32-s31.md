# ESP32-S31-Function-CoreBoard-1

Local 2.06 candidate integration; short physical checks have passed.
See [candidate validation](../release-notes/2.06-validation.md) for exact gates
and remaining hardware limits.
Publication waits for maintainer approval after testing the device web UI.

This is a separate ESP32-S31 target, **not** an ESP32-S3 variant. It uses the
onboard analog microphone through the ES8311 codec. No external microphone wiring
is needed. The speaker amplifier stays disabled. Ethernet, speaker playback and
USB host peripherals are outside this microphone integration.

## Hardware and audio

The board has 16 MiB flash and 16 MiB PSRAM; the SoC has 512 KiB main SRAM.
Capacities are not free heap. I2C SDA/SCL are GPIO51/50, ES8311 address is 0x18;
I2S MCLK/BCLK/WS/DIN are GPIO52/53/55/54. GPIO57 holds the speaker amplifier off.
The codec uses Philips I2S with a 32-bit ADC stream and MCLK at 256 times the
sample rate. CPU selection includes 40/80/160/240/320 MHz; the default remains 160 MHz.
Capture supports 8–48 kHz; incompatible microphone formats are
rejected. Gain and filtering use the existing audio pipeline.

There is no onboard microSD socket or battery divider. This integration does not
assign external SD GPIOs. Streaming, Listen and switching to Recording mode are available. SD recording
cannot start without a supported storage connection. You can save a stream on a receiving computer;
standalone SD Recording requires a separately implemented and tested storage
connection. Optional battery voltage monitoring uses **GPIO42 (ADC1 channel 0, J2 pin 20)**.
For a 1S Li-ion battery connect BAT+ through 100 kΩ to GPIO42, another 100 kΩ
from GPIO42 to GND, and BAT− to GND. Never connect BAT+ directly to the ADC.
This divider measures voltage; it does not charge the battery or imply that the
board can be powered directly from BAT+. Enable monitoring only after wiring
and calibrate against a meter. Without a battery/divider, ADC readings are not
meaningful and battery protection must remain off. Physical measurement accuracy
is unqualified until this circuit is connected.
ADC mapping: [ESP-IDF S31 ADC channels](https://github.com/espressif/esp-idf/blob/release/v6.1/components/soc/esp32s31/include/soc/adc_channel.h).

## Build and installation

All targets use Arduino-ESP32 4.0.0-RC1, based on ESP-IDF 6.1. This is a prerelease
SDK migration and requires the complete existing-board regression gate before
acceptance. The S31 Arduino variant fixes OPI PSRAM on; it has no `PSRAM` menu.
The matrix therefore adds one S31 build, retaining S3/C5 no-PSRAM builds.

```sh
python3 tools/check_build_dependencies.py --install
python3 tools/build.py --board s31
python3 tools/build.py --all --matrix
```

A project-local toolchain in `tmp/arduino-data` takes precedence when installed;
other Arduino projects can keep their existing core. Registry configuration uses
16 MiB flash and the existing dual-slot `default_8MB` partition layout (3,342,336
bytes per OTA app); unused flash is not presented as recording storage.

Initial installation is by USB UART or USB Serial/JTAG. Back up existing firmware
and settings first. Use the generated flash offsets: S31's bootloader begins at
0x2000, unlike some existing targets. Never use a XIAO/S3 merged image or copy
its offsets. On first startup join the device setup Wi-Fi and configure home Wi-Fi.

After installation, open `/ota` on the device. The app-only file is
`firmware-app-s31.bin` (or `firmware-app-s31-2.06.bin`). USB/full flash uses
`firmware-s31.bin`. Unsuffixed files remain C6 compatibility aliases.
The frozen v1.35 bridge remains for the four older targets; S31 does not use it.
Until publication, use a verified local image; public feeds do not yet offer S31.

## Qualification

Build, browser mocks, physical capture, Listen/RTSP, OTA preservation and the
maintainer's own UI acceptance are separate gates. Record actual results and
memory minima before marking this board qualified. A build does not prove audio
or long-run stability. There is no physical SD qualification without attached SD
hardware and an implemented storage route.
