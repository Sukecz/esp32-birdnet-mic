# Firmware 2.03 validation — 2026-10-31

This record covers firmware 2.03 build, browser and physical-device verification.

## Builds and automated checks

| Target | Build option | App-only bytes |
|---|---|---:|
| XIAO C3 | LTO, internal RAM | 1365808 |
| XIAO S3 | OPI PSRAM | 1277792 |
| XIAO C5 | PSRAM | 1475360 |
| XIAO C6 | LTO, internal RAM | 1384560 |

- All four normal targets built with pinned Arduino-ESP32 3.3.12 and the common
  build/SD-library helpers. Stable, versioned and manual OTA images agree. The
  manifest and OTA contract cover C3/S3/C5/C6; the permanent v1.35 bridge is unchanged.
- All 117 native/Python tests passed, including the real local nginx routing
  check. Fault tests execute the production SD allocation/worker and Listen
  sender rather than copies of their algorithms.
- Recording tests cover the low internal-heap/PSRAM case, bounded fallback and
  allocation cleanup, microphone/mode transitions, WAV rotation/finalization,
  card/capture/filesystem faults and retained settings.
- Listen sender tests cover a 2.5-second blocked send, writable-socket recovery,
  the five-second dead-peer limit, independent capture starvation, odd partial
  PCM writes and bounded preview-backlog recovery. Empty error replies allow
  CORS reading; successful audio retains its Host/Origin validation.
- Browser recovery tests cover EOF, a read that never completes, a new WAV header
  and rate after reconnect, discarded odd-byte carry, retained volume/context,
  bounded consecutive failures, immediate Stop and intentional Wi-Fi-off.
- Real browser checks cover source and embedded assets at 320/390/1280 px in both
  themes. Listen covers busy/retry/recovery/cancellation; AP password covers
  edit/revert/poll/save/error/discard, font consistency, orange drafts and overflow.

## Physical-device checks

- The final normal C6 and S3 app images were installed by local OTA. All 57
  compared settings were preserved. C6 keeps External antenna; S3 has no attached
  microphone or SD module.
- A controlled C6 preview interruption recovered through a second HTTP transfer
  without another button press, preserving the same AudioContext and 125% playback
  gain. Capture remained healthy, with the configured RTSP client connected.
- A 1.5-second pause in reading no longer closes the C6 preview. The old sender
  reproduced its short send timeout under the same test.
- On S3, a 63-character AP password including spaces survived reboot. The original
  password and all compared settings were restored. Saved mDNS OFF survives reboot;
  the original enabled setting was restored afterward.
- Final C6 Chrome playback ran for 322 seconds with all 300 observations active,
  no JavaScript errors and no send timeout. Controlled reconnection passed on the
  final C6; quick Stop/Listen and cancellation passed in source/embedded browser
  scenarios. Final capture/NTP/UTC-offset checks
  pass with zero I2S or DMA errors, and External antenna remains selected.
- Both devices serve the exact final embedded UI/setup/AP-editor assets. Their
  compared saved configuration is retained; S3's original AP password was restored
  and verified after the password-persistence test.

## Limits

C6 has a microphone but no SD module; its missing-card result is not a recording
pass. S3 checks cannot qualify real microphone sound or SD writes. C3 has no
physical target in this run. A fresh C5/PDM/AP recording and longer SD/battery
endurance remain unqualified for this release. Sense remains experimental.

Preview reconnection recovers control and current audio after a network interruption;
it cannot reproduce sound lost during the interruption. Recording has its own
separate SD queue and loss/error accounting.
