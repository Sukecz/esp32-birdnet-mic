# Firmware 2.01 validation — 2026-10-30

This record covers firmware 2.01 validation before publication. Results below
were recorded only after the corresponding check completed.

## Source audit

| Target | Build option | Streaming reserve | Recording reserve | Listen |
|---|---|---|---|---|
| XIAO C3 | LTO, no PSRAM | Adaptive internal | No RTSP ring; adaptive internal SD queue | Independent 16 KiB internal |
| XIAO S3 / Sense | OPI PSRAM | PSRAM, internal fallback | No RTSP ring; PSRAM SD queue, internal fallback | Independent 32 KiB PSRAM, 4 KiB fallback |
| XIAO C5 | PSRAM enabled | PSRAM, internal fallback | No RTSP ring; PSRAM SD queue, internal fallback | Independent 32 KiB PSRAM, 4 KiB fallback |
| XIAO C6 | LTO, no PSRAM | Adaptive internal | No RTSP ring; adaptive internal SD queue | Independent 16 KiB internal |

Streaming's requested RTSP reserve is normally 64 KiB. SD queues prefer 512 then
128 KiB PSRAM; the internal fallback is 32–128 KiB with 72 KiB headroom.
Checks and log reads allocate no SD PCM queue and retain 48 KiB internal RAM,
plus 8 KiB when the worker must be created. The first worker also needs a
contiguous block. DMA and capture/DSP buffers stay internal on every target.

The 2.00 S3 problem is reproduced in source and on the unconnected S3: PSRAM was
disabled, the RTSP ring remained allocated in Recording, and the first card check
incorrectly reused the recording memory reserve. C6 had more free internal heap
and passed that gate. Board SRAM size alone did not predict available heap.

## Listen investigation

An actual C5 Recording/Listen test reproduced a preview queue overflow after
about 50 KiB sent, with a maximum main-loop service gap of 182 ms, zero socket
errors and no send timeout. The SD recorder continued without dropped samples.
A native socket test feeding 3840 PCM bytes per 40 ms (48 kHz mono PCM16) fails
with the original single-2-KiB sender and passes with bounded catch-up. The fix
permits eight nonblocking sends and 2 ms per pass. That change alone still
overflowed on C5, so the final transport runs in its own worker with a 3 KiB
internal stack. The native worker test continues sending while the application
loop stalls for 900 ms, including a small 4 KiB fallback queue and simultaneous
stop requests. Preview overruns recover by discarding old queued preview PCM;
partially sent HTTP/PCM blocks remain intact, with normal sample alignment.
The SD queue is separate and a socket with no send progress still times out.
C6 also reproduced a queue overflow with a timely 4 ms worker service gap,
confirming the need to recover temporary transmit backpressure. Completed
post-fix results follow below.

## Completed verification

- All four normal targets built and packaged with pinned Arduino-ESP32 3.3.12.
  App-only sizes: C3 1360288 B; S3 1272320 B; C5 1469808 B; C6 1379104 B.
  The S3 and C5 PSRAM-disabled variants also compiled using separate build paths.
  CI now retains both disabled variants. The permanent 1.35 bridge is unchanged;
  the four-board manifest, versioned/stable/manual images and OTA contract agree.
- 112 native/Python tests passed with actual local nginx routing enabled. Focused
  real-socket tests also pass for bounded catch-up, recovered overruns and an odd
  partial PCM write followed by EAGAIN/recovery: the partial block stays complete
  and subsequent samples remain aligned. Worker tests cover a 900 ms application
  stall, concurrent stop acknowledgements and task-creation failure.
- Actual S3/C5/C6 app-only local HTTP OTA succeeded with reboot counters changing.
  The installed images match the final local artifact SHA-256 values. Saved
  setup, audio, recording/logging, battery, clock, network and thermal settings
  match before/after, including C5 calibration and C6 External antenna.
- Ten physical Streaming/Recording cycles on each device showed no progressive
  heap loss. Recording has zero RTSP reserve; returning to Streaming releases
  its SD PCM queue. S3 now detects 8192 KiB PSRAM and has about 174 KiB free
  internal heap after checks, compared with 76–79 KiB in the failing 2.00 setup.
- C6 without SD: actual internal SD PCM queue allocation (71456 B in the final
  run) succeeds; card absence is reported as SD unavailable. Returning to
  Streaming frees that queue. C6 capture/NTP/UTC-offset smoke check passes with
  zero I2S/DMA errors. TCP RTP reception alongside Listen produced 751 packets,
  769024 audio bytes and 384000 timestamp samples in 8.01 seconds.
- C5 at its saved 80 MHz: actual mobile UI Start, 135 seconds of uninterrupted
  Listen while recording, two one-minute rotations (three files), Stop & save,
  checked WAV header/length and zero dropped recording samples. I2S errors stay
  zero. The known startup DMA count remains 46, with no runtime increase; the
  strict zero-total smoke checker therefore is not a C5 pass criterion. Listen
  overflows/socket errors/send timeouts were zero; maximum sender service gap
  was 21 ms. Recording settings were restored after the temporary one-minute
  segment test. Starting Recording while Listen was already active also passed.
- C6 Listen stayed connected for 65 seconds; one actual preview overflow was
  recovered by discarding 16384 stale preview bytes, with no socket/send timeout.
  C5/C6/S3 transport stack reserves observed after real requests were at least
  1308/1468/860 bytes respectively, from the allocated 3072-byte stacks. The mode
  memory regression reserves an additional conservative 5 KiB task/stack budget.
- Actual device UI at 320/390/1280px in light/dark showed no horizontal overflow
  or JavaScript errors. Device-served UI bytes match the embedded assets. Source
  and embedded edit/save/discard browser tests passed. The local flasher version
  text/manifest were checked at the same widths/themes. No new settings UI exists.

The initial 2.00 C5 recording was stopped and saved before OTA: 1121 seconds,
107663404 verified bytes, zero dropped samples. Existing recordings were retained;
no card was formatted and no unattended recording is intentionally left running.
The release uses these same tested binaries. Public OTA/flasher and GitHub assets
are checked byte for byte by `tools/verify_published_release.py`; the permanent
legacy bridge stays on 1.35. Runtime evidence remains in the ignored local task
directory.

C3 has no physical test target in this task. S3 has no microphone or SD module;
its tests cannot qualify sound capture or SD writing. C6 has a microphone and
no SD module. C5's physical recording result applies to its actual card/setup,
not every supported board/card, card removal/full-card, or multi-day endurance.
Sense remains experimental and has no physical qualification here.
