# Firmware 1.23

This update improves stream diagnostics and MQTT discovery during continuous
audio streaming.

## Changes

- **Adafruit SPH0645 support:** the Audio page and API can select and persist either the existing
  ICS-43434/INMP441 Philips I2S alignment or the SPH0645 MSB/left-justified alignment. The existing
  format remains the default, and failed I2S reconfiguration rolls back.
- **Lifecycle and safety guidance:** historical INMP441 order codes reached EOL and TDK currently
  marks both legacy microphone families NRND, making the available SPH0645 useful for new builds.
  Selecting the wrong format only corrupts audio decoding and cannot electrically damage the
  microphone; wiring and supply-voltage rules still apply.
- **Stream health:** the Web UI now shows temporary TCP stalls, write failures
  and timeouts, client TEARDOWN requests and disconnects, and audio buffer
  drops/flushes separately. The last stop retains its time, stream and reason
  after a client reconnects. Counters cover all clients since device boot.
- **RTSP client cleanup:** disconnected sessions are detected correctly and
  their sockets are released. Idle-client TEARDOWN requests do not replace
  the previous streaming stop record.
- **MQTT discovery:** retained messages are sent one at a time, approximately
  one second apart, including legacy-topic cleanup. Discovery can finish while
  audio streams continuously. Failed steps retry after 60 seconds while the
  connection remains available; reconnecting starts a fresh discovery sequence.
  Each discovery socket write has a 20 ms budget, and an incomplete packet
  closes the MQTT connection before further publication.
- **MQTT status:** recovered publication errors are cleared, and discovery
  completion is displayed separately from broker connectivity.
- **Build and release validation:** Arduino CLI 1.5.0, ESP32 core 3.3.8,
  WiFiManager 2.0.17 and PubSubClient 2.8 are pinned. New tests cover discovery
  scheduling, stalled writes, UI rendering and release verification. A read-only
  tool checks all 31 GitHub/public artifacts, the OTA version and C6 aliases.

## Validation so far

All four XIAO targets (C3, S3, C5 and C6) compiled successfully, and local tests
and the OTA artifact contract passed. The existing public 1.22 distribution
also passed the new GitHub/public equality check.

Local OTA smoke tests on XIAO ESP32-C6 successfully installed 1.23 on 2026-09-08
and again on 2026-09-17. During the earlier test, at 1m 13s uptime it streamed
93 packets/s at 48 kHz with a 512-sample
buffer. MQTT discovery completed during streaming, with MQTT status `ok` and
zero I2S errors, audio buffer drops/flushes, RTSP stalls, timeouts or write
failures in that short observation.

Long-run stability, controlled failure recovery and Home Assistant entity
inspection remain pending. C3/S3/C5 are compile-tested for this version;
physical validation so far covers C6. These results do not establish that
all historical stream interruptions are resolved.

The SPH0645 code path was tested by contributor Dan Logue on his microphone. The maintainer does
not currently have that module, so independent SPH0645 hardware validation remains open.
