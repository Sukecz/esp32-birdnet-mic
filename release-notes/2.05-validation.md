# Firmware 2.05 validation

This release consolidates Recording, SD log, Battery and power editing into the
shared settings lifecycle and separates firmware responsibilities into audio
capture, RTSP, MQTT, settings persistence, mode control and OTA modules.

Existing NVS keys/defaults, OTA bridge routing, DMA/internal allocation and PSRAM
fallback policies are retained. No new task or audio queue is introduced.

## Validation procedure

- Native/Python and standalone JavaScript regression suites, including production
  settings validation and mode controller modules.
- Source and embedded browser suites, including scoped saves, failed/retried
  saves, draft/revert/discard, stale polling, typography/themes and mobile overflow.
- Six registry target configurations: C3/S3/C5/C6 and S3/C5 without PSRAM.
- Actual app, partition and ELF budgets; source/configuration/artifact hashes.
- C6 OTA, read-only UI and capture/time smoke checks, then observed runtime memory
  under actual RTSP and the optional Listen consumer.

Final measured results are recorded after the candidate build and device checks.
C3/C5 hardware is unavailable. S3 is available on older firmware without a
microphone or microSD adapter, so only read-only web/memory diagnostics apply.
SD recording, battery power/calibration and S3 candidate audio/storage behavior
are not qualified by this release.
See [hardware qualification](../docs/hardware-qualification.md) for the repeatable
soak procedure and remaining hardware matrix.
