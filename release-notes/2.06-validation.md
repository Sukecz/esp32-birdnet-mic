# BirdNETMic 2.06 candidate validation

Local candidate, pending maintainer UI review and publication approval. No push,
tag, GitHub release or public deployment has been performed for this candidate.

## Manual board and microphone selection

Automatic board/microphone probing, preferences, API choices and UI status rows
have been removed. Device configuration and Audio expose the three concrete
microphone formats and S3 board variants. Existing effective formats, tuned gain
and board selections are loaded directly. A legacy Sense SD-route marker is
folded into the explicit Sense profile, retaining external I2S when configured.
Selecting Sense or AtomS3U prefills PDM, as in the manual baseline; Sense still
allows external I2S. Old Auto API value 3 is rejected before changing settings.

Audio exposes sample rate, buffer size and I2S shift directly. Feature switches
share a visual hierarchy with indented child settings and a subtle connecting rule.
This covers filters, scheduled reboot, temperature protection, schedule, mDNS,
MQTT connection, battery/calibration/protection, SD log size and recording duration.
Independently saved details require both selected and confirmed On. Unsaved or
failed On changes cannot unlock them. Off retains saved values and orange child
drafts; Discard remains available. Grouped forms remain configurable before
activation. Battery calibration retains its existing reading/capability guards.
Noise reduction has no nested menus. Each row keeps its own Apply; the graph is
replaced by a short enabling hint when Off. Spectrum reads never replace saved
form baselines. Microphone recommendations still explicitly review High-pass.

## Connection and control refinement

Persistent Battery, low-battery protection, recording auto-start and SD logging
switches use the existing On/Off selects and common table rows. Battery monitoring
uses Apply. Calibration is directly visible; nested help/settings default open,
while top-level navigation cards retain their existing collapsed defaults.
Network presents actual Home and device Wi-Fi states before saved access details.

Recording connection is independent of startup mode and has its own scoped save.
Entering Standalone Recording starts device Wi-Fi while preserving an existing
Home connection. If Home is naturally lost, Standalone does not attempt to reconnect.
Streaming and Home Recording retain router retries and the existing AP fallback.
Explicit Recording Wi-Fi power saving still overrides both paths: its delay,
radio suspension, reconnect suppression and completion/sleep behavior are unchanged.

## Maintainer hardware observations

**S3, no microphone or microSD adapter:** earlier local candidate OTA succeeded, 8 MiB
PSRAM remained available and selected original audio, CPU and other checked
settings were preserved. Existing board/microphone choices stayed manual and
noise reduction stayed Off after updating. A 30-second observation with Listen
transport passed; this qualifies web/memory/transport with missing peripherals,
not actual audio quality or SD recording.

Actual device UI passed in both themes at 320/390/1280 px, including orange drafts,
poll/revert/discard and no settings writes. Its served embedded page matches the
candidate asset. Noise reduction allocated its engine in PSRAM. In the short
missing-microphone workload it used about 18% of audio time at 160 MHz and 36%
at 80 MHz, without automatically changing the selected frequency. This does not
qualify actual PDM capture, concurrent SD work or all 80 MHz workloads. Original
manual choices, tuned gain, CPU frequency and noise Off were restored after testing.

**C6 with microphone:** earlier local candidate OTA succeeded. Selected audio, CPU,
streaming/sleep schedule and other checked settings were preserved, including the
External antenna. Capture and actual NTP/UTC/local-offset checks passed. A
30-second RTSP PCM capture and concurrent Listen/memory observation passed.
Philips I2S capture retained tuned gain.

With noise reduction enabled at 160 MHz, a further 30-second RTSP + Listen
observation passed without increasing capture, DMA or RTSP queue-error counters.
The filter used internal RAM and about 22% of audio time on average. This is a
short observation, not extended stability or BirdNET detection qualification.
The reported internal heap minimum since boot reached about 49 KiB during the
filter workload, so further Wi-Fi/workload qualification remains important.

The same concurrent workload at 80 MHz did not pass the streaming queue check.
Do not recommend C6 noise reduction at 80 MHz for this workload; use 160 MHz.
This does not establish a universal CPU threshold for other boards or modes.
Original manual microphone selection, gain, 160 MHz, streaming/sleep schedule,
External antenna and noise Off were restored after testing. A subsequent
30-second RTSP + Listen observation passed without further queue drops, and
the final capture/NTP check passed.


## Remaining qualifications

C3/C5, Sense and AtomS3U physical qualification remains pending. No actual SD
recording or battery-runtime qualification was performed for the new filter.
Synthetic DSP tests and quieter audio do not establish better BirdNET recognition;
compare real field recordings with/without filtering, including faint calls,
continuous songs, wind and rain, before recommending it as a default.

## ESP32-S31 and shared Arduino core (2026-11-03)

The local candidate now includes ESP32-S31-Function-CoreBoard-1, its onboard
ES8311 microphone and optional external 100 kΩ / 100 kΩ battery divider on GPIO42
(ADC1_CH0, J2 pin 20). No SD support is provided for this board. Recording mode
can still be selected; actual SD recording remains unavailable. CPU selection
extends through 320 MHz, using a 16-bit saved value while retaining legacy
8-bit settings as the migration fallback.

All seven build configurations passed on common Arduino-ESP32 4.0.0-RC1:
C3, S3, S3 without PSRAM, C5, C5 without PSRAM, C6 and S31. Static memory,
physical flash/partition bounds and app/OTA size checks passed. The five standard
build receipts share clean source commit `d782e04`; packaging reuses those exact
outputs, with no second compilation. S31 has 1,449,264 app bytes and 1,893,072
bytes remaining in each OTA slot. The registry, manifest, manual OTA files,
release verifier, download statistics and current OTA routing include S31;
legacy v1.35 bridges remain immutable and limited to the original four targets.

All 27 steps of the settled source/embedded browser gate passed.
145 Python/native regressions passed, including the actual local nginx routing
checks (no skips). Codec initialization rejects invalid rates and I2C failures;
board-policy tests distinguish choosing Recording from SD availability. The
shared browser flasher was rebuilt reproducibly from ESP Web Tools 10.4.0 with
locked esptool-js 0.7.1, which supplies S31 detection and its flash stub.

Physical S31 checks passed: boot, 16 MiB PSRAM, 48 kHz microphone capture, a
45-second RTSP WAV recorded on the receiving computer, concurrent Listen,
320 MHz save and persistence across reboot, switching to Recording without SD,
10 seconds of Listen in that mode and return to Streaming / 160 MHz. After the
final local OTA, S31 and the configured C6 each passed a 45-second Listen/status
observation with no new I2S/DMA errors. NTP was actually confirmed on both devices.
Twenty selected configuration fields were compared across each final OTA; C6's
External antenna was preserved. Real device UI checks covered 320/390/1280 px,
both themes, orange drafts, polling, revert/discard and overflow.

Observed final Listen minima (API resolution 1 KiB): S31 internal free 224 KiB,
internal minimum 217 KiB, largest block 187 KiB; C6 internal free 107 KiB,
internal minimum/largest block 83 KiB. These are workload observations, not
universal admission thresholds. The C6 remained in its pre-existing Recording
mode without an attached card; this is not an SD test.

The RC SDK's C3/C6 LTO link emits mbedTLS ODR diagnostics showing private-member
spelling differences between translation units. Link and memory checks pass;
this is retained as SDK migration context, not a TLS or long-run qualification.
C3/C5 physical testing and S3 qualification on the new core remain pending.
Battery measurement accuracy is unqualified without the actual divider/battery.
Browser USB installation was not physically exercised; UART flashing and
app-only device OTA were exercised. No long-duration audio or SD qualification
is implied. Public release and deployment still require the maintainer's new
confirmation after testing the S31 UI.
